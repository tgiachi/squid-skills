# /squid:c

Replicates squid's `/comment` shortcut: find all C# **interfaces** in the current project (or in the path given as argument) and add `///` XML documentation to each interface and to every public member (methods, properties, events, indexers).

## Scope

- **Default scope**: every `.cs` file under the current working directory containing an `interface` declaration.
- **If `$ARGUMENTS` is provided**: restrict the scan to that path or glob (e.g. `src/MyProject.Core`, `src/**/Interfaces/*.cs`).
- **Always skip**:
  - `bin/`, `obj/`, `node_modules/`, `.git/`
  - Generated files (look for `<auto-generated>` header).
  - Files outside the requested path or glob when a scope is provided.

## Discovery

1. Run `grep -rln --include='*.cs' -E '(public|internal)\s+(partial\s+)?interface\s+I[A-Za-z0-9_]+' <scope>` to enumerate candidate files.
2. For each file: read it fully, locate every `interface` declaration plus every member inside it.
3. Skip an item if it already has a `///` doc comment immediately above it. Do not overwrite existing docs unless they are clearly empty stubs (`/// <summary></summary>` with nothing inside).

## What to write

Use **standard C# XML doc tags**. Be concise but useful — describe **purpose**, not signature.

**Interface**
```csharp
/// <summary>
/// <Short purpose sentence in present tense, third person.>
/// </summary>
public interface IFoo
{
}
```

**Method**
```csharp
/// <summary><Action the method performs.></summary>
/// <param name="bar"><What this parameter represents.></param>
/// <param name="cancellationToken">Token used to cancel the asynchronous operation.</param>
/// <returns><What the caller receives back.></returns>
/// <exception cref="SomeException"><Only if the contract documents the throw.></exception>
Task<Result> DoSomethingAsync(Bar bar, CancellationToken cancellationToken);
```

**Property**
```csharp
/// <summary><What this value represents and when it is set.></summary>
SomeType Value { get; }
```

**Event**
```csharp
/// <summary>Raised when <condition>.</summary>
event EventHandler<SomeArgs> SomethingHappened;
```

## Style rules

- **One** `<summary>` line when possible; multi-line only if the contract truly needs it.
- Present tense, imperative third person ("Loads the asset", not "Will load the asset" or "This method loads…").
- No filler phrases ("This interface is responsible for…"). State the contract directly.
- Match terminology already used in the codebase (read sibling files for naming).
- Do not invent behavior. If the method's purpose is unclear from name + signature + caller usage, write a minimal `<summary>` and add a `// TODO: clarify behavior with author` comment **above** the doc — never inside the doc.
- Indentation must match the surrounding code exactly (4 spaces or whatever the file uses).
- Keep the file's existing line endings (`\n` vs `\r\n`).

## Per-file workflow

1. Read the file.
2. Build a list of edits (interface + each undocumented member).
3. Apply them with `Edit` (one focused edit per item — preserve uniqueness by including a few lines of context).
4. Re-read the file once at the end to confirm the diff is clean.

## Verification

After processing all files:
- Run `dotnet build` (or `dotnet build <Solution>.slnx` if present) and report any new warnings/errors. XML doc additions can occasionally surface CS1591 if `<GenerateDocumentationFile>` is enabled — that is expected progress, not a regression.
- Print a summary:
  - Files scanned
  - Interfaces documented
  - Members documented
  - Files left untouched (already fully documented)
  - Any item where the purpose was unclear and a `// TODO:` was left

## What NOT to do

- Do not document `class` / `struct` / `record` / `enum` (out of scope — this command is for interfaces only).
- Do not reformat unrelated code. Edits must be additive.
- Do not commit. Use `/squid:cc` afterwards if the user wants a commit.
- Do not add `Co-Authored-By: Claude` anywhere.
